# Plan: Adopt MCP 2026-07-28 serving with dual-serve (HTTP + stdio)

## Goal

Serve both protocol revisions from one `adbmcp` process:

- **Legacy 2025-era clients** keep today's behavior byte-for-byte: stateful HTTP
  sessions (`initialize` creates a session, `Mcp-Session-Id` routes, `DELETE` closes),
  and the stdio initialize/initialized handshake.
- **Modern 2026-07-28 clients** are served statelessly: per-request server instances
  via `createMcpHandler`, `server/discover` answered, results carrying `resultType`,
  no protocol-level sessions.
- Bearer auth, the loopback bind guard, and the Host allowlist are enforced on **both**
  HTTP paths. stdio serves both eras via the SDK v2 `serveStdio` entry.

This completes the v0.7.0 migration started in commit `2473baa` (SDK v2 package swap).
Prior context: `docs/research/sdk-v2-2026-10.md` (dual-serve verdict), design doc §5 /
§8 item 6 (already updated), `specs/b31d7817_sdk-v2-package-migration.md`.

## Verified ground truth (recon done against the installed SDK — trust this)

Installed: `@modelcontextprotocol/server` 2.4.0, `/node` 2.1.2, `/client` 2.4.0
(dev), `/core` 2.4.0 (transitive). No dependency changes are needed — everything this
plan uses is already in `node_modules`.

From the installed `.d.mts`/sources:

- **`createMcpHandler(factory, options)` → `McpHttpHandler`** (`@modelcontextprotocol/server`).
  `McpServerFactory = (ctx: McpRequestContext) => McpServer | Server | Promise<...>` —
  called once **per HTTP request**; `McpRequestContext.era` is `'legacy' | 'modern'`
  (we ignore it: one factory, one tool surface, both eras — the SDK's own guidance).
  Options: `legacy: 'stateless' | 'reject'` (default `'stateless'` — we pass
  **`'reject'`** because we keep our own stateful session wiring for legacy traffic and
  route in user land), `onerror`, `responseMode` (default `'auto'`: single JSON body,
  upgrading to SSE if mid-call messages are emitted), `maxRequestBodySize` (4 MiB
  default, only when the handler reads the body itself). The handler is
  `{ fetch(request, options?), close(), notify, bus }` — web-standard.
  **`server/discover` is answered automatically**: `McpServer` registers the handler
  whenever its supported versions include a modern revision (default does).
  **`resultType` is added automatically** by the 2026-07-28 wire codec
  (`resultType: "complete"` lifting) — tool/resource/prompt handlers need **no
  changes**.
- **`isLegacyRequest(request, parsedBody?, options?)`** (`@modelcontextprotocol/server`)
  is the entry's own classification step exported as a predicate — routing on it can
  never disagree with `createMcpHandler`. Semantics: claim-less POSTs (including the
  2025 `initialize` handshake), body-less GET/DELETE session operations, legacy
  batches, and non-JSON/empty bodies classify legacy; anything carrying the envelope
  claim classifies modern (the modern path owns its validation-ladder rejections).
  With `parsedBody` passed it classifies from the value directly and reads nothing.
  Caveat from the doc comment: hand-wired compositions must validate Content-Type
  themselves (415 for non-`application/json` POSTs, via exported `isJsonContentType`).
- **`toNodeHandler(handler, { onerror, maxRequestBodySize? })` → `(req, res, parsedBody?)`**
  and **`toWebRequest(req, parsedBody?)` → `Promise<Request>`**
  (`@modelcontextprotocol/node`). With `parsedBody` supplied nothing is read from the
  Node stream — matches our flow (we pre-read the body for the 413 cap).
- **`serveStdio(factory, options?)` → `StdioServerHandle`**
  (`@modelcontextprotocol/server/stdio`). Default `legacy: 'serve'`: a 2025-era
  opening pins a legacy instance from the same factory for the connection lifetime; a
  modern opening is served 2026-07-28. Returns synchronously; `close()` tears down.
- **Modern request envelope** (for raw test requests): the claim rides in
  `params._meta` with keys `io.modelcontextprotocol/protocolVersion` and
  `io.modelcontextprotocol/clientCapabilities` — both required (`clientInfo` was
  demoted to SHOULD, optional). Minimal modern request:
  ```json
  {"jsonrpc":"2.0","id":1,"method":"tools/list","params":{"_meta":{"io.modelcontextprotocol/protocolVersion":"2026-07-28","io.modelcontextprotocol/clientCapabilities":{}}}}
  ```
- The v2 `Client` (`@modelcontextprotocol/client`) defaults to
  `LATEST_PROTOCOL_VERSION = 2026-07-28` and negotiates via `server/discover`; the
  existing `test/server.test.ts` (InMemoryTransport) already passes against this
  client, i.e. the modern era over a plain transport already works.
- Current `src/http.ts` (post-2473baa): legacy wiring intact on
  `NodeStreamableHTTPServerTransport`; `enableDnsRebindingProtection`/`allowedHosts`
  still set with a comment saying their replacement ships with **this** work order.

## Step 1 — `src/http.ts`: hoist Host validation to the front door

Rationale: the transport-level `enableDnsRebindingProtection`/`allowedHosts` only
exists on the legacy transport and is deprecated; `createMcpHandler` is deliberately
validation-free (migration guide: mount Host/Origin validation in front). Hoisting our
own check covers both legs with today's exact semantics.

1. Add a `hostAllowed(req: IncomingMessage): boolean` helper: exact, case-insensitive
   match of the `Host` header value against the `allowedHosts` list already built by
   `buildAllowedHosts` (unchanged — keep the exported function and its test). A missing
   Host header fails the check.
2. In `handleRequest`, insert the check **after the bearer-auth check** (preserves
   today's effective ordering: bad-auth + bad-Host answers 401, as now) and before the
   method switch: on failure `sendJsonRpcError(res, 403, -32000, 'Forbidden: disallowed Host header')`
   and `req.resume()`. (The existing test asserts status 403 only.)
3. Remove `enableDnsRebindingProtection`/`allowedHosts` from the
   `NodeStreamableHTTPServerTransport` options in `createSession()` and replace the
   now-stale migration comment with one noting Host validation lives at the front door
   for both eras.

## Step 2 — `src/http.ts`: add the modern leg and route with `isLegacyRequest`

1. New imports: `createMcpHandler, isJsonContentType, isLegacyRequest` from
   `@modelcontextprotocol/server`; `toNodeHandler, toWebRequest` from
   `@modelcontextprotocol/node`.
2. In `startHttpServer`, build the modern leg once:
   ```ts
   const modernHandler = createMcpHandler(() => createMcpServer(ctx), {
     legacy: 'reject', // 2025-era traffic is served by our stateful session wiring below
     onerror: (error) => process.stderr.write(`adbmcp: HTTP modern handler error: ${error.message}\n`),
     maxRequestBodySize: MAX_HTTP_BODY_BYTES,
   });
   const modernNode = toNodeHandler(modernHandler, {
     onerror: (error) => process.stderr.write(`adbmcp: HTTP modern adapter error: ${error.message}\n`),
   });
   ```
3. `handlePost` — after `readJsonBody` succeeds, before any session logic:
   - **415 check**: `if (!isJsonContentType(req.headers['content-type']))` →
     `sendJsonRpcError(res, 415, -32000, 'Unsupported Media Type: Content-Type must be application/json')`
     and return. (Today the legacy transport emits the 415; the modern leg has no such
     check of its own behind `toNodeHandler`, so the front door owns it for both legs.
     The existing 415 test must keep passing.)
   - **Classify**: `const probe = await toWebRequest(req, parsedBody.value);`
     `if (await isLegacyRequest(probe, parsedBody.value, { maxRequestBodySize: MAX_HTTP_BODY_BYTES }))`
     → existing legacy logic **unchanged** (session lookup / initialize-creates-session /
     400 no-session). Else → `await modernNode(req, res, parsedBody.value)`.
   - Wrap the classification in try/catch → 500 via the existing outer catch is fine;
     don't add new error shapes.
4. `handleGet`/`handleDelete`: unchanged. Body-less GET/DELETE always classify legacy;
   modern clients never send them (2026-07-28 has no session operations;
   `subscriptions/listen` is a POST stream we don't enable — the handler defaults
   suffice, subscriptions are a separate work order).
5. `close()`: also `await modernHandler.close()` alongside the session-transport
   closes (order: close sessions, then the modern handler, keep
   `closeIdleConnections` and the existing structure).
6. Update the module header comment: stateful sessions are the **legacy** leg;
   2026-07-28 traffic is served statelessly per-request; both legs share one
   `ServerContext`; Host allowlist + bearer auth enforced at the front door for both.

## Step 3 — `src/index.ts`: stdio via `serveStdio`

Replace the manual transport wiring:

```ts
import { serveStdio } from '@modelcontextprotocol/server/stdio'; // replaces StdioServerTransport import
...
// in main(), stdio branch:
const handle = serveStdio(() => createServer(ctx), {
  onerror: (error) => process.stderr.write(`adbmcp: stdio transport error: ${error.message}\n`),
});
```

- `legacy: 'serve'` is the default — 2025-era stdio clients (initialize handshake)
  unchanged, modern stdio clients now served.
- Shutdown handler: `void handle.close().finally(() => process.exit(0))` (keep
  `ctx.streams.closeAll()` first). Keep the "ready" stderr line.
- Note `serveStdio` returns synchronously (no `await connect`); the factory runs when
  the opening message arrives.

## Step 4 — `test/http.test.ts`: modern-path coverage

Add a describe block (e.g. `'HTTP transport dual-serve (2026-07-28)'`). Reuse the
existing `start()`/`postRpc` helpers. New imports: `Client` and
`StreamableHTTPClientTransport` from `@modelcontextprotocol/client` (already a
devDependency).

Define a helper for raw modern POSTs:
```ts
const ENVELOPE_META = {
  'io.modelcontextprotocol/protocolVersion': '2026-07-28',
  'io.modelcontextprotocol/clientCapabilities': {},
};
const modernMessage = (method: string, params: Record<string, unknown> = {}) => ({
  jsonrpc: '2.0', id: nextRequestId++, method,
  params: { ...params, _meta: ENVELOPE_META },
});
```

Tests:

1. **SDK client end-to-end (modern)**: `new StreamableHTTPClientTransport(new URL(server.url))`
   + `new Client({ name: 'adbmcp-modern-test', version: '1.0.0' })` →
   `client.connect()` (exercises `server/discover` negotiation) → `listTools()` has 35
   tools → `callTool({ name: 'list_devices' })` returns the emulator serial from the
   harness → `client.close()`. Track the client for cleanup in `afterEach`.
2. **Statelessness on the wire**: raw `postRpc(server.url, modernMessage('tools/list'))`
   with **no** `Mcp-Session-Id` header → 200, `tools` length 35, and
   `outcome.sessionId` is **null** (no session minted). Contrast in the same test:
   legacy `initialize()` still returns a session id (dual-serve sanity).
3. **`server/discover` answered**: raw `postRpc(server.url, modernMessage('server/discover'))`
   → 200, `body.error` undefined, `body.result` defined (keep assertions loose — the
   SDK owns the result shape).
4. **`resultType` on results**: raw `postRpc(server.url, modernMessage('tools/call', { name: 'list_devices', arguments: {} }))`
   → 200, `(body.result as { resultType?: string }).resultType === 'complete'`.
5. **Auth enforced on the modern leg**: server started with `token: 's3cret'` →
   modern `tools/list` without a token is 401; with `Bearer s3cret` is 200.
6. **Host allowlist enforced on the modern leg**:
   `rawPostWithHost(server.url, 'evil.example', JSON.stringify(modernMessage('tools/list')))`
   → 403.
7. **Routing owns its errors modern-ward**: a POST whose envelope claims an unserved
   revision (e.g. `protocolVersion: '1999-01-01'`) must NOT get the legacy
   400 'No valid session ID provided' — assert `body.error` exists and the message
   mentions the version (assert loosely; the modern path owns this error).

Existing describes (`HTTP transport sessions`, `HTTP transport security`) must pass
**unmodified** — they are the legacy-path regression net.

## Risks / watch-items

1. **Front-door Host check semantics**: the legacy transport compared the Host header
   against `buildAllowedHosts` entries; mirror that (exact, case-insensitive) rather
   than adopting the SDK's port-agnostic `hostHeaderValidation()` guard, which would
   silently widen the allowlist to any port.
2. **415 ownership**: once POSTs route to two legs, the front-door
   `isJsonContentType` check is what keeps the existing 415 test green on both legs —
   don't rely on `createMcpHandler` to do it behind `toNodeHandler`.
3. **`isLegacyRequest` body handling**: always pass our already-parsed body as
   `parsedBody` (and build the probe with it) — the stream is already drained by
   `readBody`, and cloning a used body throws.
4. **Per-request factory cost**: the modern leg constructs a full `McpServer` (35 tool
   registrations) per request. That's the documented v2 shape; fine for a device host.
   Do not add caching — statelessness is the point.
5. ** vitest client cleanup**: the modern-leg SDK client holds an SSE-capable
   transport; always `await client.close()` (tracked in `afterEach`) or tests hang.
